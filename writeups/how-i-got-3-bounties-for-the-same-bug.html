How I got paid 3 times for the same bug

Published: 07.06.2026

I've been hacking on a private program and during recon I found out that it's main application uses Backendless, a full-stack, visual app development platform and Backend-as-a-Service (BaaS). It provides developers and non-developers with the tools to build, deploy, and manage the frontend, backend, and database of web and mobile applications without writing traditional code. The front pages of Backendless were requesting API endpoints which are documented here https://backendless.com/docs/rest/index.html

I started checking every endpoint, trying to get something interesting worth reporting. Almost at the bottom of documentation there is a section regarding Caching API. At the time I was hacking, there was an endpoint to retrieve data from cache, https://xxxx.backendless.app/api/cache, and in case of my program it was responding with their customers PII, lots of details. I reported the vulnerability, it was accepted, fixed and I received a reward. Actually my first reward.

Later, I've been thinking, what if the vulnerability is back after some system update or config restore, or something else. I decided to write a Python script to be run daily, and if there is a HTTP 200 with PII, send me a notification by email. And it worked, twice, reported every time when I received an email and got my 2 more bounties.

Today, this /api/cache endpoint was removed, you cannot get all the cache, you can retrieve a part of it by <key>.
